Glossary

Terms used across these pages.

Build candidate
A build cut from trunk and registered with the artifact cache, identified by a content hash. A candidate is not a release until it has been promoted.
Sign-off
A single grading runner's recorded statement that it fetched a candidate, ran the regression suite and found it good. Signed as that runner's own id.
Quorum
The number of distinct grading runners whose sign-offs are required before a candidate is promoted. Set per release train; always more than one; counted over distinct runner identities, not requests.
Release channel
Where a promoted build's bundle is published on the artifact cache. CI reads promoted status from here.
Grading runner
An ephemeral worker that fetches candidates, runs the suite and records sign-offs. Each holds its own token and signs only as itself.
Runner token
The opaque credential bound to a runner id that proves a runner is a valid runner. Issued by the launch harness, rotated each release train.
Operator scope
Elevated scope allowing a handful of privileged actions on the grading authority, such as writing a result by hand. Granted only in an open maintenance window, out of band.
Maintenance window
A scheduled, announced period during which operator elevation can be requested and approved. Operator scope lapses when the window closes.
Release train
One scheduled cycle of cutting, signing off and promoting a release. Runner tokens and quorum config are scoped to a train.
Verdict of record
The authoritative build result consumed by CI, kept by the grading authority on the management network. Written only by grading runners during sign-off.
